# แผนก่อนเขียนโค้ด — Lab 5-3

ฐานงาน: `main` commit `3f25bad90a13b8483cdbb0fff0bf4dc3a6a5f502`

## เป้าหมาย

พัฒนาโปรเจกต์ Vue เดิมให้ครบ 4 ส่วนตาม User Stories: Todo CRUD, สมาชิกจำลอง, สีและฟอนต์, ค้นหาและกรองงาน โดยเก็บงานเดิมของทีมไว้

## ลำดับการทำงาน

1. สร้าง `dev` จากฐานเดิม และทำงานบน Feature Branch
2. `feature1.1`: แยกตรรกะ Todo, ตรวจข้อมูลว่าง, ใช้ ID ไม่ซ้ำ, เก็บข้อมูลเมื่อรีเฟรช, รองรับข้อมูลที่อ่านไม่ได้และจอมือถือ
3. `feature2.1`: ปรับ Login/Register/Logout, จดจำการเข้าสู่ระบบ, แยกงานตามบัญชี, ใช้รหัสกู้คืนในการเปลี่ยนรหัสผ่าน และระบุขอบเขตสมาชิกจำลองให้ชัด
4. `feature3.1`: ตรวจการเปลี่ยนสี/ฟอนต์/ขนาดตัวอย่าง, บันทึกการตั้งค่า, รีเซ็ตค่าเริ่มต้น และรองรับ storage ที่ใช้งานไม่ได้
5. `feature4.1`: เพิ่ม Search + Filter + Sort, ข้อความเมื่อไม่พบงาน, ล้างงานที่เสร็จแล้ว และปรับข้อมูลทีมเป็น 4 คน
6. หลังเขียนโค้ดหลักของแต่ละส่วน จึงเพิ่ม Unit Tests และรันทดสอบ ก่อนทำส่วนถัดไป
7. ตรวจ Build และทดสอบการใช้งานผ่าน browser automation; จัดทำ Manual Test ให้ผู้เรียนและเพื่อนทดสอบจริง
8. ส่ง Feature Branches และ Draft PR ไปยัง `dev`; รวมเข้า `dev` เมื่อผู้เรียนทำ Manual Test และ Peer Review ผ่านแล้ว

## รูปแบบ Branch ในรอบนี้

Codex ช่วยทำงานตามลำดับในหนึ่งรอบ: `dev` → `feature1.1` → `feature2.1` → `feature3.1` → `feature4.1` ดังนั้นแต่ละ branch ถัดไปมีงานที่ผ่านการทดสอบอัตโนมัติจาก branch ก่อนหน้า และ `feature4.1` เป็นชุดรวมสำหรับตรวจงาน ยังไม่ใช่หลักฐานว่าสมาชิกทั้ง 4 คนเขียนหรือทดสอบเอง

เมื่อทีมทำงานพร้อมกันในรอบถัดไป ให้แต่ละคนแตก feature จาก `dev` ล่าสุด แล้วเปิด PR ของตนเอง

## ขอบเขตและเกณฑ์ตรวจ

- ใช้ Vue 3 + Vite เดิม ไม่มี backend หรือบริการส่งอีเมลใน repository นี้
- บัญชีและข้อมูลเป็นแบบจำลองใน browser เครื่องนั้น การแยกบัญชีในหน้าเว็บไม่ใช่การควบคุมสิทธิ์บน server
- ทดสอบทั้งกรณีสำเร็จและผิดพลาด: ข้อความว่าง, ไม่พบงาน, อีเมลซ้ำ, รหัสผ่านผิด, รหัสกู้คืนผิด, storage เสีย/ถูกบล็อก, การสลับบัญชี และ refresh
- ไม่เขียนผล Manual Test หรือ Peer Review ว่าผ่านแทนผู้เรียน ไม่ส่ง Discord แทนผู้เรียน
- งานเดิมใน `main` และ branch เก่าต้องยังอยู่
