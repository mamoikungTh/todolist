# แผนก่อนพัฒนา — Week 6

อ่านโจทย์จาก `Agile Management - Nov 2568 (1).pdf` หน้า 153–175 ผู้ใช้เลือก Study Planner สำหรับ Lab 6-4 และต้องการชุดงานตามโจทย์ ไม่ต้องทำ PowerPoint

## ขอบเขต

- Lab 6-1–6-3: ใช้ Todo List เดิม มีเอกสาร Backlog, Burndown, Review, Feedback worksheet, Retro และบทพูดสมาชิก 4 คน
- Lab 6-4: ต้นแบบ Study Planner แยกจาก Todo ที่ `/study-planner/` ใช้ repository เดิมเป็นที่เก็บอีกโปรเจกต์หนึ่ง
- ฟีเจอร์ Sprint: วิชาและวันสอบ, รอบอ่านหนังสือ, ติ๊กอ่านจบ, กรองวิชา/สถานะและเรียงตามวัน, บันทึกใน browser
- ไม่รวมระบบสมาชิก, sync ข้ามเครื่อง, แจ้งเตือน, export และตารางลากวาง

## ลำดับพัฒนาและตรวจ

1. บันทึกแผนและแยก branch `lab6` จากชุด Lab 5-3 ที่เผยแพร่แล้ว
2. เขียน model ที่ตรวจข้อมูลก่อนบันทึก และหน้าจอ responsive สำหรับ Study Planner
3. เขียน unit tests หลังโค้ดหลัก ตรวจวันไม่ถูกต้อง, วันหลังสอบ, วิชาซ้ำ, storage เสีย, filter และสรุปเวลา
4. ตรวจ build และ browser flow เพิ่ม/แก้ไข/ลบ/อ่านจบ/refresh รวมทั้งจอมือถือ
5. จัดทำเอกสารและตัวอย่างกราฟ 5 วัน โดยระบุว่าเป็นข้อมูลจำลอง ไม่ใช่ประวัติรายวันจริงของทีม
6. ใส่แบบบันทึกข้อมูลจริงและบทพูดสำหรับวิดีโอ 3–5 / 5–10 / 5–10 / 10–15 นาที
7. ส่ง branch พร้อม Draft PR เพื่อให้ทีมตรวจ ยังไม่ merge แทนการทำ Manual Test ของนักศึกษา

## เกณฑ์สถานะ

Codex พัฒนาโค้ดตามลำดับ ไม่ใช่สมาชิก 4 คนทำงานพร้อมกัน ไม่สร้าง Daily Scrum, Stakeholder Feedback, วันที่ทำงาน, ผู้ตรวจ หรือผล Manual Test ย้อนหลัง ข้อมูลตัวอย่างมีป้ายกำกับทุกจุด ส่วนสถานะ Done ของทีมต้องตรวจ Definition of Done และบันทึกหลักฐานจริงก่อน
