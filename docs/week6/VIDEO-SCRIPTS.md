# แนวทางอัดวิดีโอ — Lab 6-1 ถึง 6-4

ใช้เป็นบทซ้อมและลำดับหน้าจอ ไม่ใช่คำยืนยันว่ากลุ่มได้ทำกิจกรรมแล้ว แทน S1–S4 ด้วยชื่อจริง เติมผลจาก TEAM-EVIDENCE และพูดด้วยภาษาของตัวเอง เวลารวมด้านล่างนับการสาธิต/พูดคุยด้วย ไม่ใช่แค่อ่านข้อความสั้น ๆ

## Lab 6-1 — เป้าหมาย 4 นาที (โจทย์ 3–5)

| เวลา | ผู้พูด | หน้าจอ/สิ่งที่ทำ | บทตั้งต้น |
|---|---|---|---|
| 0:00–0:45 | S1 | Sprint Goal และ Backlog | “Lab นี้เราจะดูความคืบหน้าของ Todo List จากคะแนนงานที่เหลือ ตัวอย่างที่เตรียมไว้มี 24 คะแนน ใช้เวลา 5 วัน คะแนนจะลดเมื่อ Story ผ่านเกณฑ์ Done ทั้งเรื่อง” |
| 0:45–1:35 | S2 | ชี้ตาราง/แกนกราฟทีละวัน | “แกน X คือวัน ส่วนแกน Y คือคะแนนที่เหลือ เส้น Ideal ลดเฉลี่ยวันละ 4.8 คะแนน ส่วน Actual ต้องมาจาก Board ของกลุ่ม สำหรับภาพนี้เป็นข้อมูลจำลอง ไม่ใช่ประวัติจริง” |
| 1:35–2:45 | S3 | ชี้ช่วง D1→D2 และ D2 | “ช่วงนี้คะแนนไม่ลด เพราะยังไม่มีงานใหม่ผ่าน Done ในตัวอย่าง D2 ช้ากว่าแผนมากที่สุด 6.6 คะแนน แต่กราฟอย่างเดียวบอกสาเหตุไม่ได้ เราต้องเปิด Daily หรือ Blocker log ประกอบ” |
| 2:45–4:00 | S4 | ปัญหาและข้อปรับปรุง | “การปิดงานวันสุดท้ายมีความเสี่ยงถ้าทดสอบแล้วเจอปัญหา เราจึงเสนอแบ่ง task ให้เล็กและบันทึกทุกวัน ก่อนส่งฉบับจริงจะใช้วันที่และคะแนนจาก Board ของกลุ่ม พร้อมอธิบายเหตุการณ์ที่เกิดขึ้นจริง” |

ถ้ามีข้อมูลจริงแล้ว ให้ใช้ค่าจริงแทนทุกตัวเลขและแก้การวิเคราะห์ตามกราฟ ห้ามพูด “ทีมเราทำเสร็จใน 5 วัน” หากมีเพียงตัวอย่างนี้

## Lab 6-2 — เป้าหมาย 7 นาที (โจทย์ 5–10)

| เวลา | ผู้พูด | สิ่งที่แสดง/คำถาม |
|---|---|---|
| 0:00–0:50 | S1 | บอก Sprint Goal และรายการผ่าน/ไม่ผ่าน DoD จากผลจริง ใช้ประโยค “ผลตรวจของทีมอยู่ในตารางนี้…” เมื่อกรอกแล้วเท่านั้น |
| 0:50–2:10 | S1 | Demo Create → Edit; ลองเพิ่มข้อความว่างเพื่อให้เห็นว่าตรวจ input |
| 2:10–3:30 | S2 | Demo Complete → Filter/Search → Delete → Refresh ให้ผู้ชมเห็นข้อมูลเปลี่ยนจริง |
| 3:30–4:20 | S3 | อธิบายข้อจำกัดบัญชีจำลองและข้อมูลใน browser; เปิดมือถือให้ผู้ทดลองดู |
| 4:20–6:10 | S3 + Stakeholder | ให้เพื่อน/อาจารย์ลองทำหนึ่งสถานการณ์เอง ถามว่าติดตรงไหน อยากปรับอะไร แล้วจด Feedback อย่างน้อย 3 ข้อพร้อมชื่อและวันที่ |
| 6:10–7:00 | S4 | เปิด Updated Backlog ชี้ว่า Feedback แต่ละข้อกลายเป็น Story ใด Priority เท่าไร เหตุผลคืออะไร แล้วสรุปสิ่งที่เรียนรู้จากการ Demo จริง |

คำถามช่วยคุย: “ถ้าใช้เตรียมงานสัปดาห์นี้ คุณหางานที่ต้องทำเจอไหม?”, “ตรงไหนต้องเดาว่าปุ่มทำอะไร?”, “ถ้าเลือกเพิ่มได้ข้อเดียว อยากได้อะไรและเพราะอะไร?” ไม่อ่าน Feedback ตัวอย่างเหมือนเป็นคำตอบจากเพื่อน

## Lab 6-4 — เป้าหมาย 12 นาที (โจทย์ 10–15)

| เวลา | คน/กิจกรรม | หน้าจอและรายละเอียด |
|---|---|---|
| 0:00–1:00 | S1 / Product Goal | แนะนำ Study Planner, ผู้ใช้, ปัญหา และขอบเขตหนึ่ง Sprint |
| 1:00–2:30 | ทุกคน / Sprint Planning | เปิด Product Backlog 8 เรื่อง อธิบายเหตุผลเลือก 5 เรื่อง, คะแนน 15, Capacity, Owner, AC และ DoD ให้แต่ละคนพูดเหตุผล Estimate ของตนจริง |
| 2:30–4:30 | ทุกคน / Daily | ใช้คลิปหรือบันทึก Daily จริงอย่างน้อย 2 ครั้ง ให้เห็น Yesterday/Today/Blocker ของสมาชิกครบ ไม่แสดงตารางบทซ้อมเป็นหลักฐานประชุม |
| 4:30–5:30 | S4 / Burndown | เปิดกราฟจากข้อมูลรายวันจริง อธิบายจุดล่าช้าและการแก้ Blocker หากยังไม่มีข้อมูล ให้ระบุว่าเป็นกราฟจำลองและยังไม่ครบงานส่วนนี้ |
| 5:30–8:00 | S2–S3 / Live Demo | เพิ่ม 2 วิชา → รอบอ่าน → แก้หัวข้อ → ติ๊กอ่านจบ → กรอง → refresh → ลบ; แสดง validation และหน้าจอมือถือ |
| 8:00–9:00 | S1 + Stakeholder / Review | ระบุ Completed/Not Completed ตาม DoD และรับ Feedback จริง แปลงเป็น Backlog ต่อ |
| 9:00–10:45 | ทุกคน / Retro | What Went Well / Didn’t / Improve; แต่ละคนเล่าอย่างน้อยหนึ่งประเด็นและเลือก Action ใหม่ |
| 10:45–12:00 | S4 แล้ว S1 | แสดงว่า A1/A2 จาก Lab 6-3 ถูกใช้ตรงไหน พร้อมหลักฐานที่มี/ขาด สรุป Reflection จากประสบการณ์จริงและสิ่งที่จะทำ Sprint หน้า |

## ก่อนเริ่มอัด

- ใช้ข้อมูลทดลอง ไม่มีรหัสผ่านหรือข้อมูลส่วนตัวจริงบนหน้าจอ
- เปิดโปรเจกต์และเอกสารที่ต้องใช้ไว้ล่วงหน้า; เพิ่มขนาดตัวอักษรให้อ่านได้
- ให้ทุกคนมีช่วงพูดและระบุชื่อของตัวเอง; ตรวจเสียงและภาพตัวอย่างก่อนอัดยาว
- ต้องมี Live Demo ของ Todo ใน 6-2 และ Study Planner ใน 6-4
- ใส่ลิงก์วิดีโอจริงใน TEAM-EVIDENCE และตรวจสิทธิ์ผู้สอนเข้าถึงก่อนส่ง Discord ด้วยตัวเอง
