## 2. Refined Product Backlog และ Acceptance Criteria

### SP-01R — วิชาและวันสอบ (อ้างอิงงานเดิม)

ในฐานะนักศึกษา ฉันต้องการจัดการชื่อวิชาและวันสอบ เพื่อให้แผนอ่านสอดคล้องกับกำหนดสอบ

Priority: Must สำหรับการตรวจของเดิม | คะแนนอ้างอิง: 3 | Owner เสนอ: S1 | สถานะ: มีโค้ดแล้ว รอทีมตรวจ

1. ชื่อวิชาหลัง trim ยาว 1–60 ตัวอักษร; ชื่อซ้ำแบบไม่แยกตัวพิมพ์เพิ่มไม่ได้
2. วันสอบเป็นวันที่มีจริง ไม่รับวันที่ไม่มีในปฏิทิน
3. ถ้าแก้วันสอบจนอยู่ก่อนรอบอ่านที่มี ต้องแจ้งเหตุผลและคงข้อมูลเดิม
4. ลบวิชาที่มีรอบอ่านอยู่ไม่ได้ ต้องลบรอบอ่านก่อน; ฟังก์ชันเดิมต้อง refresh แล้วข้อมูลถูกต้อง

### SP-02A — สร้างรอบอ่าน (แยกจาก SP-02 ที่มีโค้ดแล้ว)

ในฐานะนักศึกษา ฉันต้องการสร้างรอบอ่านของวิชาที่เลือก เพื่อแบ่งการเตรียมสอบเป็นช่วงที่ทำได้จริง

Priority: Must สำหรับการตรวจของเดิม | คะแนนเสนอ: 3 | Owner เสนอ: S2

1. เลือกได้เฉพาะวิชาที่มีอยู่ และหัวข้อหลัง trim ยาว 1–120 ตัวอักษร
2. เวลาอ่านเป็นจำนวนเต็ม 5–480 นาที; ค่าต่ำ/สูงกว่าขอบเขตและทศนิยมไม่ผ่าน
3. วันที่อ่านเป็นวันที่จริงและไม่เกินวันสอบ; อ่านในวันสอบได้; วันที่ย้อนหลังยอมรับเพื่อเก็บประวัติตามพฤติกรรมเดิม
4. เมื่อบันทึกสำเร็จมีรอบใหม่หนึ่งรายการ เริ่มเป็นยังไม่อ่านจบ; ข้อมูลไม่ถูกต้องไม่สร้างรายการ

**Given/When/Then #1**

```gherkin
Given มีวิชา Software Testing กำหนดสอบวันที่ 20 ตุลาคม 2026
When เพิ่มรอบอ่าน BVA วันที่ 20 ตุลาคม 2026 ระยะเวลา 45 นาที
Then ระบบสร้างรอบอ่านหนึ่งรายการในวิชานั้นและสถานะยังไม่อ่านจบ

Given วิชาเดิมกำหนดสอบวันที่ 20 ตุลาคม 2026
When พยายามบันทึกรอบอ่านวันที่ 21 ตุลาคม 2026
Then ระบบป้องกันการบันทึกและไม่เพิ่มรายการใหม่
```

### SP-02B — แก้ไขหรือยกเลิกรอบอ่าน (แยกจาก SP-02 ที่มีโค้ดแล้ว)

ในฐานะนักศึกษา ฉันต้องการแก้ไขหรือลบรอบอ่านที่เลือก เพื่อปรับแผนเมื่อเวลาว่างเปลี่ยน

Priority: Must สำหรับการตรวจของเดิม | คะแนนเสนอ: 2 | Owner เสนอ: S2

1. แก้หัวข้อ วิชา วัน และเวลาได้โดยใช้ validation เดียวกับการสร้าง
2. แก้ไขแล้วคง ID และสถานะอ่านจบ; ไม่เกิดรายการซ้ำ
3. กดยกเลิกแก้ไขต้องไม่เปลี่ยนข้อมูลเดิม
4. การลบมีคำยืนยัน; ยกเลิกไม่ลบ, ยืนยันแล้วลบเฉพาะรายการนั้นและยอดรวมเปลี่ยนถูกต้อง

### SP-06A — ส่งออกไฟล์สำรอง (งานใหม่)

ในฐานะนักศึกษา ฉันต้องการดาวน์โหลดแผนอ่านเป็น JSON เพื่อเก็บสำเนาไว้ก่อนล้างข้อมูล browser

Priority: Must ในชุดสำรองข้อมูลที่เสนอ | คะแนนเสนอ: 1 | Owner เสนอ: S1

1. ดาวน์โหลด JSON มี `version: 1`, `subjects` และ `sessions` โดยเก็บ ID, วันที่, นาที และสถานะอ่านจบครบ
2. ไฟล์เปิดเป็น JSON ได้และไม่เปลี่ยนข้อมูลที่อยู่ในโปรแกรม
3. กรณีไม่มีข้อมูลให้ส่งออก arrays ว่างอย่างถูกต้อง
4. การอ่านข้อมูลหรือสร้างไฟล์ล้มเหลวต้องแจ้งผู้ใช้ ไม่มีข้อความว่าสำเร็จทั้งที่ยังไม่สร้างไฟล์

ค่าที่เสนอให้ทีมยืนยัน: ชื่อไฟล์ `study-planner-YYYY-MM-DD.json`; ไม่รวมบัญชีหรือข้อมูล Todo เพราะเป็นคนละโปรเจกต์

### SP-06B — ตรวจไฟล์สำรองและดู Preview (งานใหม่)

ในฐานะนักศึกษา ฉันต้องการดูว่าไฟล์สำรองถูกต้องและมีข้อมูลอะไร ก่อนตัดสินใจนำเข้า

Priority: Must ในชุดสำรองข้อมูลที่เสนอ | คะแนนเสนอ: 2 | Owner เสนอ: S2 | Dependency: schema ของ SP-06A

1. รับ JSON schema version 1; ตรวจชนิดข้อมูล, ID ไม่ซ้ำ, วิชาอ้างอิงมีจริง และกฎชื่อ/วันที่/เวลาตามระบบ
2. ไฟล์ผิด version, JSON เสีย, session อ้างวิชาไม่มี หรือข้อมูลเกินขอบเขตต้องแสดงเหตุผล
3. เมื่อผ่าน ให้แสดงจำนวนวิชา จำนวนรอบอ่าน และจำนวนรอบอ่านจบ โดยยังไม่แก้ state/storage
4. เสนอเพดานไฟล์ 1 MB เพื่อให้พอดีต้นแบบ; ต้องให้ทีมยืนยันค่าจริงก่อน Ready และทดสอบกรณีไฟล์เกินเพดาน

**Given/When/Then #2**

```gherkin
Given browser มีแผนอ่านเดิมและผู้ใช้เลือกไฟล์ JSON version 1 ที่ข้อมูลถูกต้อง
When ระบบตรวจไฟล์เสร็จ
Then แสดงจำนวนวิชาและรอบอ่านของไฟล์โดยข้อมูลเดิมยังไม่เปลี่ยน

Given ไฟล์มีรอบอ่านที่อ้าง subjectId ซึ่งไม่มีในรายการวิชา
When ผู้ใช้เลือกไฟล์นั้น
Then แจ้งข้อมูลอ้างอิงไม่ถูกต้องและไม่เปิดให้ยืนยันนำเข้า
```

### SP-06C — ยืนยันแทนที่ข้อมูลด้วยไฟล์ที่ตรวจแล้ว (งานใหม่)

ในฐานะนักศึกษา ฉันต้องการยืนยันการกู้แผนจาก Preview เพื่อกลับมาใช้ข้อมูลสำรองโดยรู้ว่าจะเกิดอะไรกับแผนเดิม

Priority: Must ในชุดสำรองข้อมูลที่เสนอ | คะแนนเสนอ: 2 | Owner เสนอ: S4 | Dependency: SP-06B

1. เลือกได้เฉพาะไฟล์ที่ผ่าน Preview และแสดงชัดว่าเป็นการ **แทนที่ทั้งหมด** ไม่ใช่ merge
2. ปุ่มยกเลิกคง state/storage เดิมทุกค่า
3. ยืนยันแล้วตรวจ schema อีกครั้งก่อนบันทึก; ถ้าสำเร็จ state ตรงกับไฟล์และ refresh แล้วยังอยู่
4. ถ้าเขียน storage ไม่สำเร็จ ให้คงแผนเดิมและแจ้งข้อผิดพลาด ไม่รายงานว่านำเข้าสำเร็จ
5. ข้อเสนอ replace-only ต้องให้ทีม/ผู้ใช้ยืนยัน; ถ้าต้องการ merge ให้ประเมินใหม่และกำหนดกฎ ID ชนกันก่อนเริ่ม

**Given/When/Then #3**

```gherkin
Given ไฟล์ผ่าน Preview และโปรแกรมมีแผนเดิม
When ผู้ใช้กดยกเลิกการแทนที่
Then แผนเดิมในหน้าจอและ storage ไม่เปลี่ยน

Given ไฟล์ผ่าน Preview แต่ browser ไม่อนุญาตให้เขียน storage
When ผู้ใช้ยืนยันการแทนที่
Then แสดงว่าการนำเข้าไม่สำเร็จและคงแผนเดิมไว้
```

### SP-07R — แจ้งเตือนเมื่อเปิดหน้าเว็บ (งานใหม่; ยังมีคำถามสำคัญ)

ในฐานะนักศึกษา ฉันต้องการกำหนดเวลาเริ่มอ่านและรับการเตือนบนหน้าที่เปิดอยู่ เพื่อไม่พลาดรอบอ่าน

Priority: Could | คะแนนเสนอ: 5 | Owner เสนอ: S3 | ไม่ Ready จนกว่าตกลงขอบเขตการเตือน

1. ต้องเพิ่มเวลาเริ่มอ่านและเขตเวลาในข้อมูลรอบอ่าน เพราะเวอร์ชันเดิมมีเฉพาะวันที่
2. ข้อเสนอเบื้องต้นให้เตือนในหน้าเมื่อถึงเวลาและยังไม่อ่านจบ; ไม่รับประกันเตือนขณะปิดหน้าเว็บ
3. ไม่สร้างการเตือนซ้ำของรอบเดิมในหนึ่งการเปิดหน้า และไม่เตือนรอบที่อ่านจบแล้ว
4. กรณีเปิดเว็บหลังเวลา, หลายแท็บ, browser พักแท็บ และ timezone เปลี่ยน ยังต้องตกลงพฤติกรรมก่อนเขียน tests และยืนยันคะแนน

### SP-08R — ปฏิทินรายเดือนแบบดูข้อมูล (งานใหม่)

ในฐานะนักศึกษา ฉันต้องการเลือกวันบนปฏิทินรายเดือนเพื่อดูรอบอ่านและเวลารวมของวันนั้น

Priority: Could | คะแนนเสนอ: 5 | Owner เสนอ: S3

1. เปลี่ยนเดือนก่อน/ถัดไปและกลับเดือนปัจจุบันได้; วันที่ตรงกับปฏิทินจริงรวม leap year
2. แต่ละวันแสดงจำนวนรอบอ่าน และวันที่เลือกแสดงรายละเอียดวิชา/หัวข้อ/เวลา/สถานะ
3. วันไม่มีรอบอ่านมีข้อความชัดเจน; กรองวิชาแล้วจำนวนและรายละเอียดต้องตรงกัน
4. อ่านและเลือกวันได้บนหน้าจอ 320px ด้วยปุ่มหรือคีย์บอร์ด; ไม่รวมการลากเปลี่ยนวัน
5. ต้องตกลงวันเริ่มสัปดาห์, การแสดงปี พ.ศ./ค.ศ. และจำนวนรายการก่อนพับเก็บ ก่อนยืนยัน UI/Estimate
